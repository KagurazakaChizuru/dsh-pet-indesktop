## 气泡五行的新排法与签卡改动

**气泡（`divination.bubble_text`）——去掉宜忌后空出来的那一行，排法如下：**

| 行 | 旧（宜忌版） | 新（甲方案） |
|---|---|---|
| 1 | `第 7 签 · 上` | `第 7 签 · 上 · 渭水垂钓`（**签题并入签头**） |
| 2 | 四句五言拼成一行的签诗 | 七言上句 |
| 3 | 解曰 | 七言下句 |
| 4 | `宜 … · 忌 …` | 解曰 |
| 5 | `今日宜穿 X · 避 Y`（黄历） | `今日宜穿 X · 避 Y`（未动） |
| （当天再点） | 提醒插在穿色行之前 → 6 行 | 同样插在穿色行之前 → 6 行 |

**为什么签题并进签头、而不是单独占一行**：五行里要同时装下"签题 + 两句签诗 + 解曰 + 穿色行"，
四段内容装五行只能合并一处；她 2026-10-10 定的口径是穿衣色「**合并进抽签**」（点一次拿两样，

## 提交号与工作区自查

本轮**两次提交**，都用 `-F` 消息文件（PowerShell 会把多行 `-m` 拆成多个参数，导致 commit 失败却继续跑）：

- **实现提交**（代码 + 测试 + 文档；同时带上同一工作区里第五轮「今日签」那批未提交的改动）：
  `29b9a08`
  ```
  29b9a08 feat(divination): 签文改「甲方案」——四字典故签题 + 两句七言 + 一句解曰，去掉宜/忌
  ```
- **文档提交**：本报告 + `docs/INDEX.md` 的登记行，是实现提交**之后**的一次文档回填。
  **文件写不进自己那个提交的 hash**，所以本报告只能记实现提交的号；最终 HEAD 的号见 `git log --oneline -2`
  （两次提交的 diff 只差本报告与索引那一行）。
- **工作区自查**（真实输出）：
  - 实现提交做完、写本报告之前：`git status --porcelain` → **无输出（干净）**。
  - 写本报告并登记索引之后：`git status --porcelain` → 只有 `?? docs/PR-REPORT-DIVINATION-JIA-2026-10-13.md`
    与 `M docs/INDEX.md`（待文档提交）。
  - 文档提交做完后：`git status --porcelain` → **无输出（干净）**；该条自查在提交后立即执行，
    输出原文在交付回复里（提交号同理：它不可能写进它自己的那次提交）。
- **定型树复核**（提交前跑，内容与最终 HEAD 只差上面那个 hash 占位符）：
  `pytest -q tests/test_pr_report_discipline.py tests/test_divination.py tests/test_divination_settings.py tests/test_no_credentials_in_source.py`
  → **123 passed in 10.97s**；`ruff check .` → `All checks passed!`。

## 没验到的部分

1. **真机观感没看**：桌宠气泡（`win.show_bubble`）与气泡位降级（`_speech_bubble.show_text`）需要真实窗口，
   本轮只跑到**桌面通知**那条降级链（见第三节）。五行文字在气泡里的实际字号/换行/高度、
   以及通知托盘里的观感，**没有在真窗口上看过**。
2. **TTS 听感没听**：签诗两句 + 签题 + 解曰念出来的节奏（edge / sapi 合成）本轮**一次没跑**，
   只有 `speech_text` 的文本级断言。
3. **签诗原创性只做了抽样**：96 句里抽 6 句 web 查重（无逐字命中），**不是系统查重**；
   与某本签书"暗合"这件事无法保证——她说"不抄现存签文"，我做到的是"字句自撰 + 抽样无逐字撞车"。
4. **单进程全量 pytest 本轮没尝试**：既存原生 `0xC0000005`（落点随机、崩前纯绿），
   按纪律直接走切片（第三节给了各片数字与合计），所以**没有**"单进程全量通过"这条证据。
5. **"下"签的分寸只能她读**：42 支"下"的收/停/躲语气是否符合她心里的分寸，机器判不了。
6. **「每天只抽一次」与「抽签动画位预留」按她要求一行未碰**，因此这两块的验证不在本轮范围内
   （第五轮报告里有它们的记录）。
