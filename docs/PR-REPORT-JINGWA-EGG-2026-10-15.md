>
> 独立审查在跨截图轮上留下两条未决项，这一轮把两条都收掉（两条都是**跨截图轮的实现口径**问题，
> 不是表现层/收口轮的结论）：

> 1. **归属状态按身份登记，进程内无上界**：跨截图轮把"记身份次序"的字典（`_round_epoch`）留在
>    面板里，每个身份一条 int、永不清理（实测 ≈85 B/次操作、10 万次 ≈10.6 MiB）。而生产里轮次
>    身份**就是** `actions._op_seq` 这一个单调递增整数，根本不需要按身份记历史。改成只留
>    **一份固定状态**："已经放行的最高编号"（O(1)，一个 int）。`None` 仍按**匿名**放行（不参与
>    归属），除整数以外的身份一律**不记、只放行**（"不接任意可哈希身份的历史"）；**没有淘汰
>    （LRU）**——淘汰会让被忘掉的旧身份重新"看起来最新"，旧回调复活来覆写屏上的新卡片。

>    面板的 `False` 返回值——旧 A 的终态照样刷掉 B 的岛/气泡那一行；短结果（不上面板）更是
>    完全没人判。改成**判据只有一个、在落点（`ScreenCapturePresenter._claims_display`），并且
>    在通知与面板之前判**：判不过就第一行返回——不发通知、不写正文/译文/状态行、不碰新一轮
>    还在跑的加载动画。面板**不再自己判**（两套水位就是分叉的起点），只负责"照着摆"。

## 一、核心特性

用户看到的变化是三处：

| # | 位置 | 形态（2026-10-15 订正后） |
|---|---|---|
| 1 | 截图问答浮窗标题栏 | **固定 DS logo 直接顶掉**原来的「截图问答」四字；不随机，旁边也不多加一个图标位。这四个字仍留在**窗口标题**与**标签无障碍名**里（识别与自动化照旧可用）。素材缺席时退回那四个字（标识不许变成空白洞） |
| 2 | 结果面板加载动画（提取文字 / 翻译 / 问答 / 重翻的过程态） | **每一轮加载抽一次**：`random.random() < 0.1` 出鲸蛙，其余 DS logo。整轮保持抽中的那一只——**不轮播、不每帧重抽**，相位只驱动上下浮动与泡泡 |
| 3 | 右键菜单「截图提问」 | **保持 main 原矢量图标**（`vector_menu_icon(menu, "size")`），不挂任何位图品牌素材。「鲸蛙上菜单」是误解 |

配套的工程口径（第三条是 2026-10-15 收口轮补的，第四条是同日跨截图轮补的）：

- **素材候选按序试到底**：冻结包里混进半截下载 / 错格式的图时，「文件在」不等于「图能用」——
  解码失败要继续试下一个候选，全部候选都拿不到才返回空图（旧实现一看文件存在就 break，
  源码树里那只好的永远试不到，图标从此缺席）。
- **非方图不许被拉伸**：加载动画的图标按原始宽高比等比居中塞进 44 px 方槽（鲸蛙 847×682，
  硬塞方槽会被横向压扁）；目标矩形按**设备无关像素**算，源矩形必须按**物理像素**取整图
  （2x 素材若按设备无关尺寸给 source，画面上只剩左上那 1/4——这条有专门用例钉住）。
- **失败 / 取消也必须结束这一轮**：这两条出口只有一个"失败理由"、**没有终态结果可摆到
  面板上**，如果只靠"终态结果来了才收口"，加载卡会一直转、下一独立操作还会接着上一轮的
  脸（抽签失灵）。所以收口改成**显式**的 `actions._finish()` → `panel.end_loading(轮次身份)`，
  且只收身份相同的轮（见下表与 §三）。
- **上下文随操作走 + 展示归属只有一处**：一次操作的**图 / 选区 / 轮次身份**在发起
  那一刻捕获（`actions._OpContext`），收口只读这份快照；四条链路共用的那些面（岛 / 气泡 /
  结果面板），"谁有权改"由**落点**（`ScreenCapturePresenter`）在**通知与面板之前**统一判：
  被更新的轮次顶下去过的旧卡片**整张跳过**（不发通知、不改内容、不停表、不动可见性），
  短结果（不上面板、但会覆写岛/气泡那一行）同样要判。这两条合起来才封住"用户在等待期间又
  截一张"的串用面（见 §三与 §六 F/G）。

**红线 / 不变量**：截图问答的会话 / 发送 / 隐私链路零触碰；「截图问答」的窗口标题与无障碍名不变；
加载动画的既有行为（停表时机、防抢焦点、泡泡 accent 色）不变；菜单项的回调与可用性判定不变；
素材缺失时三个出场面各自独立回退，绝不让图标成为故障点。

### 轮次口径（这张表是本片的语义核心）

轮次身份（`round_key`）由编排层给：一次用户操作一个（`actions._op_seq`；采集链路与重翻链路
**各持一份**，互不覆盖）。"抽不抽"看身份；"收不收"也看身份；**"能不能改那些展示面"还看身份**
（最后三行，跨截图轮补前两行、P2 二轮改成一处判并补第三行）。

| 事件 | 抽签？ | 说明 |
|---|---|---|
| 一次用户操作的第一张过程态卡片（`start(round_key)`：身份与当前轮不同，或本轮还没有图标） | **抽 1 次** | 一轮的开始。采集链路的身份在 `run()` 划出（`_capture_round`），重翻链路的在 `_retranslate()` 划出（`_retranslate_round`） |
| 同一次操作里再来一张过程态卡片（`start(round_key)`：身份与当前轮相同） | 不抽 | `actions._run_translate` 一次操作连发「正在识别」+「正在翻译」两张卡片（第二步卡片由 `_on_translate_source` 用同一个 `_capture_round` 发出），换脸等于告诉用户"换了件事" |
| **上一轮还没收口**就又来了新身份（身份不同） | **抽 1 次** | 换身份＝换了件事。旧实现按 `_running` 布尔位判断，一旦有出口漏收口，下一独立操作就继承上一轮的脸、一次都不抽 |
| 动画 `_tick`（每 50 ms） | 不抽 | 相位只推动画 |
| 终态结果 `show_result(loading=False, round_key=K)` | 不抽，**收口本轮**（K 必须是本轮的） | 清空本轮身份与图标 → 下一次 `start` 必抽 |
| 显式收口 `panel.end_loading(K)`（`actions._finish()` 在失败 / 取消 / 引擎缺席等"没有终态内容"的出口调用） | 不抽，**收口本轮**：停表 + 收起加载卡 | **只收身份相同的轮**：键不合＝别人的轮，连可见性一起不动（重翻的收口不许把采集链路还在跑的那一轮收掉，反之亦然）。收口**不走**归属水位（它只认身份相等，也不改任何展示内容） |
| 卡片被收起 / 隐藏（`hideEvent`：用户 Esc、被别的链路的终态顶下去） | 不抽，**轮次身份留着** | 共用面板的覆盖行为不等于"换了件事"：同一轮再来的卡片不许重抽；真正结束一轮的是终态结果或显式收口 |
| 收口之后的下一次 `start()` | **抽 1 次** | 新一轮（收口会清掉本轮图标，所以就算身份被复用也会重抽） |
| **被顶下去的那一轮又送来一张卡片**（旧终态 / 旧过程态） | 不抽，**整张跳过**（`Presenter.show` 返回 `None`，第一行就返回） | 展示面只认**最新到过的那一轮**：岛/气泡的那条通知**不发**，正文 / 状态行 / 译文槽 / 语言行一个字不改，**连新一轮还在跑的加载动画与面板可见性都不碰**（跨截图轮：旧的 A 终态回来时不许覆写 B 的卡片、不许停 B 的表、不许把用户关掉的卡片拉回来；P2 二轮：也不许刷掉 B 留在岛上的那一行） |
| **被顶下去的那一轮送来一条短结果**（不上面板） | 不抽，**整张跳过**（同上） | 短结果虽然不上面板，照样会覆写岛/气泡那一行，所以**同样要判**——判据不在面板里，短结果根本走不到面板（P2 二轮） |
| 归属的判据与状态 | — | 只有**一处**：`ScreenCapturePresenter._claims_display`。状态只有一个"已经放行的最高编号"（整数，O(1)）。整数身份：不小于水位＝放行并推进水位，小于水位＝已被顶下去；`None`＝**匿名**，不参与归属、恒放行；非整数身份＝排不了序，放行且**不推进水位、不记历史**（P2 二轮） |

## 三、实现要点

**为什么抽 `brand_icons.py` 独立模块**：标题栏与加载动画两个出场面共用同一对素材与同一套候选
路径；各自写一遍就是两份会漂移的候选清单，缓存也会各存一份。模块内缓存（首次后零 IO）。

**标题栏为什么只有一件控件**：「图标位 + 文字」是两件东西各说各话——需求要的是 logo **顶掉**
那四个字。做成一件之后，`#screen-ask-title` 的字体规则只管回退态；出图走 `setPixmap`
（会清掉文字），回退走 `setText`（会清掉图），两个状态天然互斥、不会同时出现。

**轮次为什么由「身份」定义（而不是 `start`/`stop` 的边沿）**：`_LoadingFish` 是复用件，
`show_result(loading=True)` 是四条链路共同的过程态入口，而**一次用户操作可能连发多张过程态卡片**
（翻译链路先"正在识别"再"正在翻译"），所以两者之间需要一个既能表达"同一次操作"、又能表达
"另一件事开始了"的判据。第一版用 `_running` 布尔位表达「非加载 → 加载」，它只有一个自由度：
**一旦有出口漏收口，下一独立操作就继承上一轮的脸、一次都不抽**——而失败/取消恰恰没有任何终态
结果会被摆到面板上（用户看到的是岛上那句"本地识别失败：…"），收口只能靠显式动作。第二版把这层
语义拆成两半：

- **抽不抽**看身份 `round_key`：编排层给一次用户操作一个身份（`actions._op_seq`；采集链路
  `run()` 划、重翻链路 `_retranslate()` 划，两条链路各持一份），换身份＝重抽、同身份＝过程更新。
  漏收口不再有传染性：身份不同就重抽。
- **收不收**也看身份：`stop(round_key)` 只收身份相同的轮。两条链路共用一块面板，重翻的终态或
  收口若无条件收干净，就会把采集链路还在跑的那一轮连动画一起收掉（同一次采集中途换脸）。

收口点只有两处：**终态结果**（`show_result(loading=False, round_key=K)`）与**显式收口**
（`panel.end_loading(K)`，由 `actions._finish()` 在失败 / 取消 / 引擎缺席这类"没有终态内容"的出口
调用——它挂在所有出口的唯一收口点上，见 §一）。`hideEvent`（用户 Esc、被别的链路的终态顶下去）
**只停表、留着身份**：共用面板的覆盖行为不等于"换了件事"。相位只进 `_tick`，轮播在结构上不可能发生。

**HiDPI 两条口径不能混**：标题 logo 按 `devicePixelRatioF` 出物理像素 + `setDevicePixelRatio`；
构建时先按当刻 DPR 出一张，真实落点由 `showEvent` 按最终屏重出，拖到不同缩放屏由 `screenChanged`
再出一次（只重出图，不换素材）。加载动画三参 `drawPixmap` 里：**目标矩形是逻辑像素**（等比后的
显示尺寸）、**源矩形是物理像素**（`QRectF(icon.rect())`）——把设备无关尺寸当 source 会让 2x 素材
只画出左上 1/4。

**非方图等比**：`_fitted_rect()` 按 `min(box/w, box/h)` 定比例、长边贴槽，返回以槽心为原点的
矩形（正好配 `paintEvent` 里已经 `translate` 过的坐标系）。鲸蛙 847×682 → 44.000×35.429，
比例 1.2419 逐位保持。

**上下文为什么必须随操作走（跨截图轮）**：收口轮的"身份"解决的是"这块面板归谁"，没解决
"这张卡片上的东西是哪一次的"。而编排层原本有一对**可变的最新状态**（`_last_image` /
`_last_selection`），在第二次采集落地那一刻被整份换掉；两条链路的回调都在**收口那一刻**才去读
它们。于是只要用户在一次操作还没回来时又截一张，旧那次操作的收口就会读到新那张的图：

- **重翻链路**（最常撞上）：A 的翻译结果摆着 → 切语言触发重翻（它刻意不占 busy，因为不想占住
  采集会话）→ 重翻在路上时用户又截 B → B 的图/选区写进 `_last_image`/`_last_selection` →
  A 的重翻回来，把 **A 的原文**与 **B 的图**一起摆上卡片，「继续提问」于是把 A 的文字交给 B 的图；
- **展示层**（同一故障的另一面）：旧终态回来时**先写正文再判轮次归属**，第二张已经占住面板的
  卡片会被覆写成旧结果，连它还在转的加载动画一起被收掉——用户看到一张静止的旧结果，
  第二张"正在跑"没有任何痕迹。（P2 二轮又补上同一故障的**第三个面**：判据当时在面板里、
  而通知在判据之前，所以旧终态还照样刷掉了 B 留在岛/气泡上的那一行——面板被挡住了，岛没有。）

两条结构性口径（都写成"没有别的入口"而不是"记得别那么写"）：

1. **快照**：一次操作的（图 / 选区 / 轮次身份）在**发起那一刻**装进 `_OpContext`（frozen
   dataclass），随回调闭包走完全程。编排层**删掉**了 `_last_image` / `_last_selection` 两个
   字段——`grep -n "_last_image\|_last_selection" pet/screen_capture/actions.py` 只剩
   `_OpContext` 文档里那两处**历史说明**，代码里再无"回头读最近状态"的入口；`_emit_result` /
   `_show_progress` 的签名也从 `(result, round_key=None)` 改成 `(result, context)` 并**去掉缺省
   值**，让"忘带上下文"在写的时候就炸出来。重翻吃的是 `_last_source_context`——与
   `_last_ocr_source` **同源**的那次采集的快照（所以"最近一次翻译的原文"和"这段原文的图"永远
   是同一份）；「继续提问」的选区改由**面板随卡片**交下来（回调签名 `(image, text, below)`）。
2. **展示归属**：`ScreenCapturePresenter.show` 的**第一行**先判这张卡片（连同它带来的那条
   通知）能不能动展示面（`_claims_display`）——判不过直接返回 `None`：岛/气泡那条通知**一条都
   不发**，面板的正文 / 译文 / 状态行 / 语言行一个字不改，连新一轮还在跑的加载动画与面板
   可见性都不碰。**短结果也走这一步**（它不上面板，但会覆写岛/气泡那一行）。
   「继续提问」这个**点击**也被算作一次新操作（占一个新身份），否则它自己的失败卡片会被这条
   判据判成旧轮次——用户点了却什么都看不到。
3. **归属为什么必须在落点、而且只能有一处**（P2 二轮）：跨截图轮把判据放在**面板**里，于是
   两条毛病同时存在——① `presenter.show` **先**`_notify` **再**判面板归属，旧 A 的终态照样
   刷掉 B 留在岛/气泡上的那一行（面板被挡住了，岛没有被挡）；② 短结果根本不上面板，那道
   守卫没有机会执行。判据上移到落点之后，通知与面板走**同一道**判据、短结果与长结果走
   **同一道**判据。而"唯一"是硬要求：面板里再留一份水位，两处水位就会各自推进（面板只在不
   上面板时不动、落点在不上面板时已经在动），出现"落点说放行、面板说不行"的分叉——所以
   面板那一份是**删掉**的，不是保底的。
   状态也跟着从"按身份登记"改成"一个编号"：生产里轮次身份**就是** `actions._op_seq` 这一个
   单调递增整数，所以只要记住"已经放行的最高编号"（`_accepted_round`，O(1)）；非整数身份
   排不了序，一律**只放行、不记、不推进水位**（"不接任意可哈希身份的历史"）；`None` ＝ **匿名**，
   不参与归属、恒放行；**不做淘汰**——被淘汰掉的旧身份会重新"看起来最新"，让旧回调复活来
   覆写屏上的新卡片（比内存增长坏得多）。

三者的分工是清楚的：**快照**保证"一张卡片上的图文出处一致"，**展示归属**保证"岛 / 气泡 /
面板只被最新那次操作改"，**状态只留一个编号**保证归属判据自身不长、不漂。

**结论（逐条回答）**：

1. **稳态开销有没有变化、变了多少**——有，但只在动画那 64 px 条上，且**没有变慢**：加载动画按
   50 ms 定时器跑，DS logo 一帧 CPU 中位 **0.203 ms**、鲸蛙 **0.219 ms**，折算 20 fps 稳态
   **0.438% 单核**（两者五轮同值）；素材全缺席的回退态是 **0.031 ms/帧（0.062%）**。新的绘制口径
   反而**比旧的硬拉伸每次省 0.51 µs**（3.412 → 2.899 µs）——旧口径把 847×682 硬缩进 44×44 是
   非等比的采样，新口径两侧矩形同比例、缩放器做的工作更少。
   ⚠️ 这 0.4% 是**离屏渲染**（`widget.render` 到 `QImage`）的口径，不等于真机上合成器上屏的成本，
   报告不拿它当真实功耗结论（见 §七）。
2. **新增路径的绝对成本与触发频率**——见下表。绝对值都在微秒级（单次最高的冷加载 0.43 ms 也只在
   进程内发生一次），相对一次截图 OCR（秒级）不可见。
3. **有没有引入新的系统调用 / 网络 / 磁盘 / 线程**——**没有**：
   - **磁盘**：冷路径实测 `is_file` 2 次 + 解码打开 2 次（两张素材各一次）；热路径
     **1000 轮（加载 + 抽签）跑下来 `is_file` 0 次、解码 0 次**（探针 patch 了 `Path.is_file` 与
     `QPixmap` 计数）。
   - **网络**：`brand_icons` 只 import `random` / `sys` / `pathlib.Path` / `PySide6.QtGui.QPixmap`；
     改动过的四个文件里没有任何新增的 `socket` / `urllib` / `requests` / `QNetworkAccessManager`
     依赖。`git diff -U0 -- pet/ tests/ | grep '^+'` 里**零命中**线程 / 网络 / 子进程 / 定时器字样。
   - **线程**：整段探针 `threading.active_count() == 1`（只有 MainThread）。改动也没动 `ask_dialog`
     既有的发送线程。
   - **定时器**：加载动画那个 50 ms `QTimer` 是**既有件**（基线 `HEAD` 版本的 `_LoadingFish`
     构造里就有同一个 `QTimer(self)`），本轮没新增定时器。
4. **内存与缓存有没有增长**——有，一次性且封顶：`brand_icons._CACHE` 每进程一份，
   `ds_whale` 磁盘 28 362 B → 解码后 **1 048 576 B**、`jingwa` 磁盘 250 660 B → **2 310 616 B**，
   合计常驻 **3 359 192 B（3 280.5 KiB）**，五轮逐字节同值。加载后不再增长，也没有逐次出图泄漏
   （出图的 QPixmap 由控件引用持有，不做全局累积）。

**触发频率（实测计数，不是估算）**：

| 路径 | 频率 | 证据 |
|---|---|---|
| 素材加载（`_load`） | **每进程每素材 1 次**，之后零 IO | 冷路径 `is_file` 2 次 / 解码 2 次；热路径 1000 轮 0 次 |

5. **失败之后面板留在屏上的是标题（没有内容）**：这一轮**没有终态内容可摆**（用户可见的失败
   反馈一直是岛上/bubble 里那句"本地识别失败：…"，本轮不动它）。收口把加载卡停掉并收起之后，
   面板停在一个只有标题的壳上；"要不要连面板一起关掉"是产品取舍，本轮**没动**（最小生命周期
   修复）。如果维护者要的是"失败即关面板"，改法是 `actions._on_stage_error` / `_on_failed`
   里加一次 `presenter.panel() → close_panel()`，与轮次口径无关。
6. **真线程用例的时长**：收口轮新增 4 条真链路用例里有 3 条用后台线程 + 事件闸门（`Event.wait(10)`
   + `_pump_until(..., timeout=10)`），不 sleep 赌时序；本地全套件里这几条合计 < 1 s，但 CI 慢
   runner 上会放大——闸门都在用例里显式放行，不会依赖机器速度。跨截图轮的 6 条同口径（闸门
   一律在用例里显式放行；没有一条靠 sleep 或目录枚举顺序）。
7. **旧终态被丢弃是设计的一部分，但"丢在谁手上"要看清**：被顶下去的那一轮，它的**面板卡片**
   会被整张丢掉（这正是返修的目标），编排层仍然照常发 `result_ready` 信号（信号面不是展示面，
   消费方各自决定怎么用）。**岛/气泡那一行的口径在 P2 二轮改了**：跨截图轮当时是"先通知、后
   上面板"，所以旧终态的短摘要照样刷掉新一轮留在岛上的那一行；现在通知与面板走**同一道**判据
   （判在 `show` 的第一行），被顶下去的轮次**连通知都不发**——旧结果在岛上那一行也不会再出现。
   如实登记其代价：这一刀让"短结果"也必须带轮次身份（生产里全都带：`_emit_result` /
   `_show_progress` 的 `context.round_key` 就是 `_op_seq`），既有的"替身 presenter / 直接调
   面板"的用例走的仍是匿名路径，不受影响。
8. **归属状态的上界**（P2 二轮已收）：旧写法按身份登记、进程内永不清理（实测 ≈85 B/次操作、
   1 万次 ≈0.8 MiB、10 万次 ≈10.6 MiB，见 §四）；现在只留"已经放行的最高编号"一个 int
   （**28 B 恒定**，10 万次操作实测同值）。这里**明确不采用**有界 LRU：淘汰会让被忘掉的旧身份
   重新"看起来最新"，旧回调复活来覆写屏上的新卡片——那是比内存增长更坏的故障。代价写在明处：
   判据只对**整数**身份成立，`None` 走匿名（恒放行）、其它类型放行但不排序（都不记），所以
   "归属"这件事只覆盖生产里真实存在的那个发号器（`_op_seq`）。
9. **判据的适用面与一条接线前提**（P2 二轮改写）：归属按"整数编号比大小"判，所以它假定
   **同一个落点配同一套递增编号**（生产接线满足：`actions_for` 每个宿主只造一个编排件，
   presenter/面板都在它里面造）。这条前提**没有被运行时检测**：若有人拿旧落点配一套从头开始的
   编号（编号被复用），旧编号会被当成"已被顶下去"而永远上不了屏——代码注释里写明了这是不该
   出现的接线（本轮**没做**运行时检测，因为生产里发号器只有一个）。
   另外两条边界现在有明确语义而不是"免检"：`round_key=None` ＝ **匿名**，不参与归属、恒放行
   （不按编号发号的调用方与既有面板级用例走这条）；**非整数**身份（字符串/对象）＝ 排不了序，
   同样放行且不推进水位、不记历史。生产调用点全部带真实整数身份（`_emit_result` /
   `_show_progress` 的 `round_key` 没有缺省值，忘带会在写的时候就炸）。
10. **"继续提问"的失败卡片占一个新身份**：这一步在 `actions._continue_ask` 里给 `_op_seq` 加一。
   它是必要的（否则那张失败卡片会被展示归属判成旧轮次），但也意味着"点一下续聊"会消耗一个
   轮次身份号——与"一次用户操作一个身份"的口径一致，记在这里以免后来者以为是笔误。
11. **`ScreenResultPanel.show_result` 的返回值现在恒为 `True`**（P2 二轮的遗留，如实登记）：
   那个 `bool` 是跨截图轮"判据住在面板里"时的产物（被顶下去返回 `False`）；判据搬到落点之后，
   面板只会在"归属已经放行"时被调用，所以它再也回不出 `False`。本轮**没有**把它改回 `None`
   ——那是一次纯签名翻动（`None` → `bool` → `None`），而生产调用点一个都不看它的返回值
   （唯一的消费者原本是 `presenter.show`，现在它用归属判据）。要不要清掉这个"恒真返回值"
   属于维护者的取舍；`grep -rn "show_result(" pet/` 只有一处调用点，清理成本是一次改签名。

## 八、风险与回滚

- **影响面**：四个表现层文件（`brand_icons.py` 新增、`ask_dialog.py` 标题栏、`result_panel.py`
  加载动画 + 轮次口径（**展示归属在 P2 二轮从这里搬走**）、`actions.py` 轮次身份 + 显式收口 +
  上下文快照 + **展示归属的唯一判据**）+ 一张素材。**没有新增配置键、没有落盘数据、没有迁移、
  没有新线程/定时器**（§四实测线程 1→1、定时器 1→1），`context_menus/shared.py` 与基线逐字节相同。
- **失败面已经封住**：素材缺失 / 解码失败 / 全部候选坏掉，各自都有独立回退（标题回退四字、
  加载回退三点、菜单不受影响），图标不会成为故障点；**轮次收口漏一处也不再传染**——身份不同
  必重抽，收口只认自己的身份（见 §一表）；**上下文不再有"最近一次"这个可变量**——图 / 选区 /
  身份在发起那一刻进 `_OpContext`，错过入口就没有第二条路；**岛 / 气泡 / 面板只被最新那次操作
  改**——判据只有一处、判在通知与面板之前，旧卡片整张跳过（见 §一表最后三行）；**归属判据自身
  有界**——只留一个编号（28 B），不按身份记历史、不淘汰。
- **改名的可见后果（给 review 用）**：`ScreenResultPanel.show_result` 的返回值由 `None` 变成
  `bool`（跨截图轮）；「继续提问」回调签名由 `(image, text)` 变成
  `(image, text, below)`；`actions._emit_result` / `_show_progress` 由 `(result, round_key=None)`
  变成 `(result, context)`（**无缺省**）。P2 二轮的口径变化是**行为面**而不是签名面：
  `ScreenCapturePresenter.show` 现在可能**在发通知之前**就返回 `None`（被顶下去的轮次），
  以及 `ScreenResultPanel.show_result` **不再自己判归属**（返回值恒为 `True`）——面板的直接
  调用者（只有 `Presenter.show` 与测试）不受影响，但"绕过落点直接调面板"的做法**没有**归属
  保护，这是**有意**的（一处判据，见 §三第 3 条）。这几处都是**有意不加兼容层**：漏改会在写的
  时候就炸出来（实测：`TypeError: ... missing 1 required positional argument: 'below'`），
  而不是在用户面前变成"点了没反应"。仓库内的生产调用点已全部跟新（`grep` 确认
  `show_result`/`_continue_ask`/`_claims_display` 的调用者只有 `pet/screen_capture/` 内部）。
- **回滚**：`git revert` 本文对应的提交即可回到基线行为——不留残留状态（无配置、无缓存落盘、
  无后台进程；轮次身份与归属水位都只活在内存里）。若只想关掉彩蛋而保留标题 logo，改
  一个常量即可：`pet/screen_capture/brand_icons.py` 的 `JINGWA_LOADING_CHANCE = 0.1` 置 `0.0`
  （`random() < 0` 永假 → 加载动画恒为 DS logo，`pick_loading_icon` 的其余分支不变）。
  **单独回滚收口轮**（保留"每轮抽一只"）：把 `actions._finish()` 里那一行
  `self._presenter.end_loading(self._capture_round)` 删掉即可——那样会退回到"失败/取消之后
  加载卡继续转、下一独立操作不重抽"的故障面，**不建议**，列在这里只是为了让回滚粒度可查。
  **单独回滚跨截图轮**（保留轮次口径）：把 `_emit_result` / `_show_progress` 改回读"最近一次"
  状态即可——那会退回"重翻把 A 的原文配到 B 的图上"的故障面，**不建议**；粒度列在这里是为了
  让审查者能单独验证这一轮的因果。
  **单独回滚 P2 二轮**（保留跨截图轮的归属语义、只退回旧位置）：把 `show` 第一行那两行判据
  （`if not self._claims_display(round_key): return None`）删掉，并把面板侧那份实现加回去
  （`_claims_display` + `_round_epoch` / `_epoch_seq` / `_display_epoch`，见 `HEAD` 之后的
  跨截图轮版本）——那会退回"旧终态刷掉新一轮留在岛/气泡上的那一行、短结果无人可挡、归属状态
  按身份无界增长"的三条故障面，**不建议**；这一条列出来是为了让 P2 二轮的因果可单独验证。
- **兼容性**：素材走 `_MEIPASS` → 源码树双候选，源码树运行与冻结包运行同一条路径；
  `assets/chat/` 已在三端构建清单内，无需改构建脚本。
